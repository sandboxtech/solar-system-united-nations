# United Nations of Sol：场景实现计划

本文档用于指导场景从空目录逐步发展到可长期运行的 Space Age 多人场景。开发顺序优先完成最小经济闭环，再逐步加入星球灾难、学习、盗窃等高风险系统。

当前进度：阶段 0～4 已实现，其中阶段 0～2 已在游戏内验证通过。阶段 5 的五颗公共星球错峰预警、撤离、异步清图、换种重建、表面统计归零、随机星球属性和保存状态机已经实现。阶段 8 的 90 小时离线玩家清理也已实现；每小时最多删除一名非管理员，并先回收场景资产与引用。上述新功能已通过静态检查，仍需按文末清单进行 Factorio 双人游戏内验证。

## 一、已经确定的核心规则

- 使用 Factorio 2.0 与 Space Age，包含品质。
- 保持纯场景实现，不制作或依赖额外的配套 mod；只使用游戏与 Space Age 已有原型。
- 所有玩家属于同一个势力。
- 金币是保存在 `storage` 中的场景货币，不是 Factorio 的金币物品。
- 每位玩家首次建立账户时获得 1000 初始金币；已有账户不会重复领取。
- UBI 按游戏时间每秒累计 1 金币，在线与离线玩家相同；使用时间差懒计算，不周期性遍历玩家发放。
- UBI 最多积累 30 小时，玩家通过联合国概览手动领取。
- 每个玩家只能在 [planet=nauvis] 建立一个个人关联箱；其他表面放置木箱不转换，房产内部的关联箱不计入该限制。
- 关联箱是 `linked-container`，相同势力、原型与 `link_id` 共享同一个末影库存。
- 每分钟按在线玩家结算一次，通过 `LuaForce.get_linked_inventory(prototype, link_id)` 直接取得共享库存，不逐个遍历关联箱实体。
- 房产成交时，只需把该房产所有关联箱的 `link_id` 改为新主人的个人 `link_id`。
- 房产没有保护期，任何时候都可以买走。
- 房产价格持续下降，最低价格为 1；成交后，本次成交价成为新的基准价格 `P`。
- 玩家房产总寿命为 30/120/480 小时，对应价格周期 T 为 3/12/48 小时；每颗星球另有三套永久小房 T=3 小时和一套永久中房 T=12 小时。
- 房产基础税率默认为 10%，管理员可动态调整；实际交易税率按卖方总等级降低。每颗星球另有默认 100 套的房产软上限，降低上限不删除已有房产。
- 屋主购买自己的房产仍按正常交易更新价格，只净支出税款，不另设续期机制。
- 玩家直接转账每笔至少 1000 金币；手续费从收款所得扣除，为向上取整的 0.1%，最低 100 金币。
- 房产页的犯罪按钮允许玩家消耗 1000 金币与 10000 体力，随机尝试进入当前所属星球另一名玩家的一套有主房产；成功率按目标当前报价计算，太空平台禁用，并全服广播结果。完整判定显示在按钮 tooltip。
- 玩家金币余额没有玩法上限；房产实际成交价最高为 `1,000,000,000`。
- 公共星球计划提前警告并重置；玩家将被撤离到联合国难民营。
- 默认权限不允许使用蓝图。
- 物流机器人配方始终禁用；科技研究完成后再次强制禁用，避免研究效果将其解锁。
- 每名玩家同时最多拥有一艘飞船；新建飞船宽度为 `16 + 总等级 × 2`，寿命为 `12 + 总等级` 小时，高度最大 512。玩家可在任意地点选择任意公共星球轨道建造，固定消耗 10000 体力。

## 二、统一后的房价模型

实现时避免同时用 `t` 表示时间点和经过时间，统一采用以下变量：

- `P`：上一笔实际成交价格。
- `D`：当前价格下降到 `P` 的游戏刻。
- `T`：房产降价周期；由玩家房产的总寿命档或永久基准房大小决定。
- `a`：管理员设置的价格倍率，`1<a<100`，默认 2。
- `tax`：管理员设置的房产基础税率。

所有时间使用 `game.tick`，不使用现实时间。

```text
price = min(1,000,000,000, max(1, ceil(P × a^((D-now)/T))))
```

成交后：

```text
P = 本次成交价
D = now + T
```

因此，刚成交后的再次购买价格约为本次成交价的 a 倍；经过一个周期后回落到本次成交价；之后继续下降。

设卖方总等级为 L，每次交易：

```text
actual_tax_rate = tax × 1 / (L / 100 + 1)
payout = floor(成交价 × (1 - actual_tax_rate))
```

普通交易使用卖方等级。屋主购买自己的房产时卖方也是自己，只需有足够余额支付税款，但仍以完整当前报价成交，并令 `P=成交价、D=now+T`。总等级只降低交易税率，不改变房价公式或价格回落速度。房产实际成交价限制在 `1,000,000,000` 以内。

金币没有玩法上限。第一版使用 Lua 数字保存金币，并拒绝 NaN 和无穷值；如果余额最终超过 `2^53-1`，整数将无法保持个位精度。除非实际服务器经济接近该范围，否则不引入复杂的大整数实现。

## 三、简洁 UI 原则

### 常驻工具栏

左上角常驻界面保留玩法说明、个人、房产、玩家和一个地图标记“家”按钮。角色在公共星球时，该按钮前往本星球最近到访且仍自有的房产，没有则前往本星球难民营；角色在房产或难民营时返回对应星球原点。所有判断使用 `physical_surface`，不受 remote view 影响。

普通玩家的主窗口保留六个页面：

1. 玩法说明
2. 个人（低保、经验、自杀）
3. 房产
4. 星球（五颗公共星球的重置倒计时）
5. 飞船（顶部建造/拆除、全服飞船与剩余寿命）
6. 玩家

所有玩家看到“建造”页；管理员额外看到“管理”页。非管理员不会创建管理页签，晋升或降级时立即重建窗口。

窗口中的非交互文字、表格、空白和内容区域都可作为拖拽面；按钮仍优先响应点击。

好友管理已进入玩家页，金币转账保留 `/un-transfer`；每笔至少 1000 金币，付款方另付 `max(100, ceil(金额×0.1%))`。管理员功能集中在只对管理员可见的管理页。

### 个人页

低保区域只显示领取所需的信息：

- 当前金币余额。
- 无文字的 UBI 容量进度条。
- 一个“领取 当前可领 / 最大金额”按钮，不重复显示具体金额。

飞船页顶部提供建造和二次确认拆除，不显示“进入飞船”按钮；下方按玩家稳定排列全服飞船及其剩余寿命。飞船建造仍只允许在 [planet=nauvis]。

经验区域每种科技瓶一行：图标、累计转换数量、下一级门槛和等级贡献。每项数量的十进制位数就是该项等级，12 项相加为总等级；只有关联箱实际消耗的科技瓶才计入经验。

顶层“前往星球”专指 [planet=nauvis]，优先抵达关联箱附近；没有关联箱时抵达原点附近。“前往联合国难民营”抵达难民营原点附近。场景不提供五颗公共星球之间的传送；死亡复活仍优先抵达关联箱附近，没有关联箱时抵达联合国难民营原点附近。

### 房产页

- 使用五颗星球的真实页签，每套房产只出现在所属星球页内。
- 玩家至少持有一套房产时，列表上方显示“全部自有房产是否对外开放”的开关；未持有房产时隐藏。
- 每行显示名称、所有者、剩余总寿命、当前价格和“购买/进入”按钮。
- 选中后才显示税率、太阳能、水、矿物、防护等详细信息。
- 购买前使用一个简短确认框，显示付款、卖方所得和税款。
- 排序必须稳定；价格相同时以房产 ID 作为最终排序键。
- 管理员默认遵守普通房产进入权限；管理页启用“管理员可进入任意房产”后，才可绕过产权和出发表面限制直接进入。
- 每次购买房产后向全服广播买方、成交价、卖方（如有）、卖方实收、税款和房产名；屋主自购也广播。

### 星球页

- 按固定星球顺序显示五颗公共星球，不显示通行状态或传送操作。
- 每秒刷新距离下次重置的 `时:分:秒`；异步清理期间显示“清理地图”。
- 重置状态机在重置前 5 分钟及重置开始、完成时向全服广播；页面只读取同一状态，不另建倒计时。

### 玩家页

### 管理员页

- 显示账户、房产、飞船、个人关联箱和金币流水等 `storage` 摘要。
- 可动态修改新账户初始金币、好友上限、新飞船寿命、离线清理时间和全部房产税率。
- 可暂停公共星球重置和科技失传，并控制管理员能否进入任意房产；后者默认关闭。科技失传的判定间隔、最大强度，以及玩家新建房产的初始价格倍率、三档寿命、三档 T 和每星球房产上限均可即时调整。
- 可创建、二次确认删除、修复房产，并为玩家设置金币；金币修改写入带管理员索引的流水。
- 新建房产从编号 1 开始查找第一个未被记录或 surface 占用的编号；异步删除完成后，该编号可以复用。
- 不提供任意 Lua 或任意 storage 键编辑，避免破坏存档结构。

- 按在线状态、名称和玩家编号稳定排列全部注册玩家。
- 显示在线/离线状态、累计在线小时、累计离线小时和客户端语言。

### 刷新与提示

- GUI 只在打开、操作完成、余额变化或低频刷新时更新，不每 tick 重建。体力、低保和星球倒计时每秒更新；房产、阵营、玩家、飞船与经验列表最多每 5 秒更新一次，房产权属 revision 变化仍在下一次每秒检查时立即重建。
- 灾难只在关键时间点提示，例如 30 分钟、5 分钟、1 分钟和开始时。
- 普通结算不持续刷聊天；使用汇总提示或只更新界面。
- 玩家看到自然语言，不暴露 `storage` 键、`link_id` 或内部状态名。

## 四、代码结构

计划采用小型模块结构，由 `control.lua` 集中注册事件，避免同一事件在多个模块重复注册。

```text
control.lua
config.lua
scripts/
  state.lua
  scheduler.lua
  economy.lua
  experience.lua
  linked_inventory.lua
  properties.lua
  surfaces.lua
  disasters.lua
  learning.lua
  gui.lua
  commands.lua
  restrictions.lua
  ships.lua
  permissions.lua
locale/
  zh-CN/locale.cfg
  en/locale.cfg
```

模块职责：

- `state.lua`：初始化 `storage`、版本号和一次性迁移。
- `scheduler.lua`：GUI 显示、瓶子结算、灾难倒计时等低频任务；UBI 本身不使用周期任务。
- `economy.lua`：金币增减、整数与有限值检查、交易流水。
- `experience.lua`：累计科技瓶消耗、十进制等级和下一门槛。
- `linked_inventory.lua`：个人 `link_id`、公共关联箱限制、共享库存结算。
- `properties.lua`：房价、购买、续费、双向好友权限、动态供需、房产关联箱换主。
- `surfaces.lua`：联合国难民营、房产表面、传送与安全落点。
- `disasters.lua`：警告、撤离、异步清理、重新生成和恢复开放。
- `learning.lua`：科技瓶经验、等级与效果。
- `gui.lua`：唯一的玩家主窗口和小型确认框。
- `settings.lua`：校验并持久化管理员动态设置。
- `restrictions.lua`：在初始化和科技研究完成后强制禁用受限配方。
- `ships.lua`：飞船归属、创建、等级尺寸、等级寿命和原生入口锁定。
- `permissions.lua`：禁用蓝图以及后续离线清理规则。

持久数据保存稳定 ID、玩家索引、表面名称和箱子位置。不要依赖跨表面清理仍然有效的实体引用；执行操作时重新解析并检查 `.valid`。

## 五、分阶段实施

### 阶段 0：技术试验与规则配置

目标：在正式搭系统前验证两个关键引擎行为。

- 建立最小 `control.lua`。
- 确认场景启用了 Space Age；缺少依赖时给管理员明确提示。
- 试验木箱手动放置后替换为可用的 `linked-container`。
- 验证修改 `link_id` 后库存切换行为。
- 验证没有具体实体引用时，通过 `LuaForce.get_linked_inventory` 取得库存。
- 验证最后一个关联箱消失后，该关联库存和其中物品的生命周期。
- 试验目标星球表面的安全清理方式和异步完成事件。
- 建立集中配置：默认降价周期 2 小时、最长未来时间 30 小时、房产价格上限 `1,000,000,000`、UBI 和默认税率。

完成标准：两个玩家可以用不同 `link_id` 看到各自库存；换号后房产箱立即切换；表面清理不会把后续初始化放在异步清理完成之前。

### 阶段 1：场景骨架、金币与最小 UI

目标：玩家进入场景后能看到简洁且可靠的联合国界面。

- 初始化版本化 `storage`。
- 创建玩家金币账户和确定性的交易流水序号。
- 实现金币增加、扣除、转账底层函数；所有调用检查余额、上下限和失败退款。
- 实现按 `game.tick` 懒计算的离线 UBI、30 小时容量与手动领取。
- 建立一个“联合国”入口和概览页。
- 创建中英文 locale，所有玩家文本均使用本地化键。
- 处理玩家加入、离开、重连、重生和移除。

完成标准：双人游戏中余额一致；重载脚本与保存重开后余额不丢失；UI 不重复创建、不刷屏。

### 阶段 2：个人关联箱与瓶子出售

目标：完成第一个可玩的赚钱循环。

- 监听玩家手动建造木箱事件，并替换为个人关联箱。
- 每个玩家在全部公共星球合计最多一个，机器人建造暂不自动注册。
- 房产内部的脚本预设箱不计入该限制。
- 玩家拆除或箱子被摧毁时清理注册状态。
- 每分钟只遍历 `game.connected_players`。
- 通过玩家势力、关联箱原型与个人 `link_id` 直接取得库存。
- 关联箱消耗科技瓶并增加对应个人经验；所有瓶种与品质均按实际数量转换。
- 单次结算形成一条汇总流水，不按物品堆或箱子刷多条记录。
- 概览页显示关联箱状态和最近一次收入。

完成标准：同一共享库存不会因多个房产箱而重复结算；离线玩家不出售；库存不足或箱子消失时行为正确；金币计算不会产生负数、NaN 或无穷值。

### 阶段 3：联合国难民营与房产最小闭环

目标：玩家能够赚钱、买房、进入房产，并通过换主自动切换末影库存。

- 创建联合国难民营表面和安全出生点。
- 每颗星球初始化三套永久 64×32 基准房和一套永久 128×64 基准房；除此之外不创建系统房产。玩家选择 64×32、128×64 或 256×128，并从所属星球采样地貌。
- 房产与 [planet=nauvis] 同步昼夜参数、周期和相位，太阳能效率统一固定为 10%，夜间最低亮度统一固定为 0.05；[planet=nauvis] 重建并改变昼夜长度后会重新同步全部房产。
- 每颗公共星球各有一个 64×64 教学网格难民营；新房产只从其所属星球远方确定性采样全部地砖及树、岩石，虫巢、资源、单位和建筑不复制。房产中央使用正方形教学网格：长宽不等时边长为较短边，长宽相等时边长为房产边长的一半。
- 玩家建造房产时可一次性命名；留空则使用“星球 + 屋主 + 可复用编号”的默认名，编号从 0 开始且省略 0。建成后不可改名。
- 每套房产在北侧虚空显示名称；默认名按查看者语言本地化，自定义名直接显示房主输入的文字。表面名称使用同一名称。
- 在“建造”页统一消耗自动化科技包经验和固定体力建房，不消耗金币。经验成本与总寿命成正比，再乘 1/3/5 的尺寸费用倍数；不设置额外建造冷却。管理员页只保留修复，不提供创建或删除。
- 实现房价计算、最低价、最高价和展示倒计时。
- 实现原子购买流程：再次校验价格、扣买方、付卖方、回收税、更新产权。
- 每套房产中央 2×2 格固定放置四个关联箱；成交后全部切换到新主人的 `link_id`。
- 实现房主续费和未来 30 小时限制。
- 实现房产列表、详情、购买确认和进入按钮。
- 传送前检查真实身体位置、车辆状态、目标表面和安全落点；找不到安全落点时强制传送到目标表面的 `(0, 2)`。
- 房产中央的正方形区域固定为教学网格；其余区域不人工拼接地形，保持来源样本的连续自然分布。正方形房产的教学网格边长为房产边长一半，长方形房产则等于较短边。
- 铺设自然样本时启用引擎地块边缘校正，使不同地块使用原生平滑过渡，不显示人工锯齿边界。

完成标准：两名玩家连续购买同一房产不会产生负余额或重复付款；点击确认时若价格已变化，拒绝旧报价并刷新；换主后所有房产箱立即显示新主人库存。

### 阶段 4：好友与金币转账

目标：支持合作，同时保持产权边界清楚。

- 每名玩家最多设置 10 名好友；好友关系保存在玩家账户而非房产上。
- 只有双方互相添加为好友时，才可以进入对方房产；好友不能出售、续费或修改对方产权。
- 屋主至少持有一套房产时，可在房产页统一切换全部自有房产是否向所有玩家开放；公开状态只授予进入权限。
- 房产易主无需迁移好友数据，进入时始终根据新屋主与访问者的当前双向好友关系重新校验。
- 实现金币转账命令或小型对话框。
- 转账直接成交，无需确认且没有限额；必须校验正整数、收款玩家和余额，并记录双方流水。

完成标准：权限在服务端点击处理器中重新验证，不能通过旧 GUI、改名或重连绕过。

### 阶段 5：五颗公共星球与灾难重置

目标：形成“公共开发—撤离—重建”的服务器循环。

- 管理 [planet=nauvis]、[planet=vulcanus]、[planet=gleba]、[planet=fulgora]、[planet=aquilo] 的开放状态。
- 每颗星球的联合国难民营只连接该星球原点与该星球房产，不提供跨星球传送。
- 为每颗星球保存本轮属性、下次灾难时间和生命周期状态。
- 五颗星球错峰计时，提前预警并在清理前关闭进入；处理实体控制、远程查看、离线角色和关联箱注册失效。
- 灾难状态机：正常、预警、停止进入、撤离、清理地图、重新开放。
- 使用 `game.tick` 安排灾难，随机属性使用同步的 `math.random`。
- 清理前停止传送和新投送，撤离玩家真实角色，并处理远程查看。
- 尊重表面异步清理完成事件，再恢复出生点、必要设施和本轮属性。
- 将关联箱注册与被重置的实体分离；实体消失后允许玩家重新建立。
- 每轮更换地图种子并异步执行 `surface.clear(true)`；清理完成后重建并重新开放，不重置科技。
- 重置对应星球的生产、击杀等 statistics；[planet=nauvis] 重建时把虫群进化度设为本轮随机值。
- 每轮从该星球的特色池抽取 3 个不重复词条，倍率叠加在基础随机地图参数之上并显示于星球页；保存恢复后不会重复抽取，互斥词条不会同时出现。

实现状态：代码完成。每颗星球每轮按 `下限+(上限−下限)×random(0,1)^a` 小时独立抽取下次周期，默认 0.5～2.5 小时、a=2；提前 5 分钟预警。上下限和 a 可由管理员调整并从下一次抽取生效。每轮随机种子、资源、地貌、气候、太阳能倍率和昼夜，[planet=nauvis] 另随机虫群进化度。等待双人游戏内验证预警、远程查看、载具、离线角色、清理地图期间强行进入和保存重开。

完成标准：至少用两名玩家测试预警、远程查看、死亡、离线角色、在途物流和重建；保存重开不会重复触发或跳过灾难阶段。

### 阶段 6：经验与公共科研维护

目标：加入长期成长，但不破坏前面的经济平衡。

- 经验为 0 时等级为 0；否则等级为经验值的十进制位数。
- 每种瓶子保存独立经验。
- 经验和等级均无上限；总等级影响新飞船尺寸、寿命和房产卖方税率。
- 新建飞船的宽度为 `16 + 总等级 × 2`，地图高度最大 512；飞船建成后不因后续升级自动扩宽。
- 科技失传默认每小时独立判定一次：每轮共用 `x=random(0,0.25)`，失传概率为 `x%×不重复科技瓶种类数`；用于解锁事件的特殊科技和当前研究直接依赖的科技免疫，无限科技只降低一级。管理员可关闭或调整判定间隔和最大强度，间隔改变后从当前时刻重新排期。
- 学习页只显示等级、进度和简短效果。

完成标准：关联箱与科研不会同时消耗同一物品；所有瓶种与品质均严格按实际数量增加个人经验；重生、换角色和重连后个人效果能正确恢复。

### 阶段 7：星球随机属性与订单经济

目标：使每轮公共星球重建具有不同生产价值。

- 为每颗星球定义有限且可解释的属性池。
- 每轮只改变少量属性，避免玩家无法理解。
- 在概览和交通界面显示本轮关键属性。
- 可选：增加联合国科研委托，使不同科技瓶的经验需求周期性变化。
- 订单变化与灾难重建错峰执行，避免同一 tick 集中更新。

完成标准：随机结果在多人中确定一致；属性对新生成区域生效；UI 能用一两行解释变化。

### 阶段 8：长期离线与管理工具

目标：最后加入破坏性和争议性较高的机制。

- 盗窃暂不实现。
- 玩家连续 90 小时未上线时删除玩家；房产先变为空置，中央关联箱改为无主，然后删除个人关联箱、飞船和全部好友引用，再由引擎删除离线玩家，最后清理金币、经验和相关流水。
- 自动任务每小时最多处理一名玩家，默认豁免管理员，避免同一 tick 批量执行破坏性工作。
- 玩家建房二次确认时重新检查选项、所属星球状态和对应科技包经验。

完成标准：只删除确实连续离线 90 小时的玩家，关联实体和产权不会留下悬空玩家索引。

### 阶段 9：多人压测、迁移与发布

目标：把功能集合变成可长期维护的场景。

- 使用两名以上玩家测试每个交易和权限边界。
- 检查所有周期任务，避免同一分钟集中扫描全部系统。
- 检查无序表迭代是否会影响付款、随机选择或显示顺序。
- 为已有存档准备显式、一次性的版本迁移。
- 校验所有 locale 的键和占位符一致。
- 运行场景检查脚本和 Lua 语法检查。
- 编写服务器安装、Space Age 依赖、更新、迁移和回滚说明。

完成标准：保存重开、脚本重载、玩家重连、多人同时操作和灾难期间退出均不会破坏持久状态。

## 六、每阶段固定验证流程

每个阶段都执行：

1. 静态检查和 Lua 语法检查。
2. 新存档初始化测试。
3. 旧存档重载与保存重开测试。
4. 两个客户端同时操作测试。
5. 失败路径测试：余额不足、对象已失效、价格变化、表面正在删除。
6. 检查聊天与 UI 是否产生重复提示。
7. 记录无法在命令行验证、必须进 Factorio 测试的步骤。

## 七、规则决定与尚待确认的问题

### 已确认，可以开始阶段 0

1. 保持纯场景，不制作配套 mod。
2. 每次成交后，房价降到新 `P` 的时间点为 `now + 2小时`。
3. 续费把该时间点继续向未来推 2 小时，但续费后不得超过 `now + 30小时`。
4. 玩家金币余额不设玩法上限；房产实际成交价最高为 `1,000,000,000`。

### 可在实服测试后调整

- 瓶子成长：所有瓶种与品质按实际数量转换为个人经验，并按固定周期处理。
- 房产：动态供需的阈值在实服观察后是否需要调整。
- 关联库存：玩家最后一个关联箱消失时，其中物品是否允许随库存消失，还是需要隐藏的永久锚点箱。
- 灾难：每颗星球每轮周期为 `下限+(上限−下限)×random(0,1)^a` 小时，默认 0.5～2.5 小时且 a=2；清空整颗星球并提前 5 分钟预警，三项周期参数可按实服节奏调整。
- 公共科研：2 倍科技倍率的准确含义，以及科研维护值的下降与恢复速度。
- 长期离线：当前房产回归空置，管理员默认豁免；可根据实服管理规则调整。

这些数值全部进入 `config.lua`，先使用保守默认值运行测试，不把平衡参数散落在业务代码中。
