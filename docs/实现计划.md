# 维护说明

## 真相来源

- `config.lua`：新存档默认值、房型、星球与阵营配置。
- `scripts/settings.lua`：可由管理员动态调整并保存到 `storage` 的设置。
- `scripts/`：实际运行规则。
- `locale/zh-CN/locale.cfg` 与 `locale/en/locale.cfg`：主要玩家文案。
- `README.md`：项目主页与玩家玩法概览。

如果文档与代码冲突，以当前配置和运行代码为准。

## 维护原则

- 玩法正文只说明目标、下一步操作和直接后果。
- 公式、概率和边界放在 tooltip，不要重复到多个文档。
- 实现细节只出现在管理员说明或代码注释。
- 不为旧脚本与新 locale 混用增加兼容层；服务器更新时应完整替换场景并执行必要的脚本重载。
- 公共星球跃迁、房产删除和玩家清理必须保留失败兜底与有效性检查。
- 高频任务应使用事件、版本号和懒计算，避免周期性完整遍历大型列表。

## 将来停止兼容 Factorio 2.0

当前 `info.json` 保持 `factorio_version = "2.0"`，四项原版依赖的最低版本也保持 `2.0.0`。

因此使用 Factorio 2.1 新建地图时，游戏会显示三条原版迁移信息：

- `molten-iron -> iron-ore-melting`
- `molten-copper -> copper-ore-melting`
- `wood-processing -> tree-seed`

它们来自 Factorio 2.1 的 `space-age/migrations/ore-melting.json` 与 `tree-seed.json`，不是场景脚本打印，也不影响玩法。

以后确认不再兼容 Factorio 2.0 时：

1. 将 `info.json` 的 `factorio_version` 改为 `2.1`。
2. 将 `base`、`elevated-rails`、`quality`、`space-age` 的最低版本改为 `2.1.0`。
3. 提升场景版本号。
4. 用当时准备上线的 Factorio 2.1 版本新建存档，确认不再显示上述迁移信息。
